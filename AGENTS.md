# databraryr – Agent Guide

This is the **R client package** for the Databrary API — a CRAN-published wrapper (`install.packages("databraryr")`) for building reproducible data-wrangling, analysis, and visualization pipelines against data stored on [Databrary](https://databrary.org). It is a standalone R package (not part of the `databrary-core` ecosystem) and the R sibling of [`databrarypy`](../databrarypy/). Built on **httr2**, with OAuth2 auth, retry, pagination, and binary/zip downloads, exposing functions for volumes, sessions, folders, records, assets, users, institutions, search, uploads, and bulk operations.

- R >= 4.3.2; lifecycle: **stable**; version `1.0.0.9000` (dev).
- Upstream repo: `https://github.com/databrary/databraryr`; site: `https://databrary.github.io/databraryr/`.

## Architecture in brief

- **Requests**: every call starts from `make_default_request()` (in `make_default_request.R`), which builds an `httr2` request with the base URL (`DATABRARY_BASE_URL`), `USER_AGENT`, `Accept: application/json`, retry (`RETRY_LIMIT`), and timeout (`REQUEST_TIMEOUT`). By default it attaches an OAuth2 `Authorization` header and refreshes the token if near expiry.
- **Auth/token state**: `login_db()` performs the OAuth2 password grant; the token bundle (access/refresh tokens, expiry, client id/secret, username) is cached in a package-private environment (`auth_state.R`) and can optionally be persisted via **keyring** (`login_db(store = TRUE)`). `token_helpers.R` / `auth_service.R` handle refresh.
- **Config**: credentials and host come from environment variables read from `.Renviron` — `DATABRARY_CLIENT_ID`, `DATABRARY_CLIENT_SECRET`, `DATABRARY_LOGIN`, optional `DATABRARY_PASSWORD` (else prompted via **getPass**), and optional `DATABRARY_BASE_URL` (defaults to `https://api.databrary.org`; point at staging here). Package options are managed via the **options** package.
- **Endpoints**: each public function lives in its own `R/` file with a parallel `tests/testthat/test-*.R`. Functions return tibbles/lists; downloads write to disk or return raw content.

## Do / Don't

**Generated files**

- DON'T hand-edit `NAMESPACE` or anything in `man/` — both are generated by **roxygen2**. Edit the roxygen comments above the function in `R/` and run `devtools::document()` (the `.Rprofile` does this on session start).
- DON'T edit `README.md` directly — edit `README.Rmd` and re-knit. The header says so explicitly.

**Adding/changing endpoints**

- DO add each new endpoint as its own `R/<verb>_<noun>.R` file, following the existing naming (`list_*`, `get_*`, `search_*`, `create_*`, `update_*`, `patch_*`, `delete_*`, `bulk_*`).
- DO build requests via `make_default_request()` rather than constructing `httr2::request()` from scratch, so auth, retry, user-agent, and timeout stay consistent.
- DO add a matching `tests/testthat/test-<name>.R` and `@export` + roxygen docs (with `@examples`) for any user-facing function.

**Auth & secrets**

- DON'T manage tokens ad hoc in endpoint functions — token caching/refresh lives in `auth_state.R` / `token_helpers.R` / `auth_service.R`.
- DON'T commit credentials. Real values belong in a developer's own `.Renviron`/keyring, never in tracked files. Tests requiring live auth should skip gracefully when credentials are absent.

**Conventions**

- DO keep lines within the lintr limit (120 chars) and respect `.lintr` exclusions; new constants generally go in `CONSTANTS.R`.
- DO update `NEWS.md` for user-visible changes, and bump `Version` in `DESCRIPTION` per CRAN/semver conventions when releasing.
- DO keep vignettes runnable (they gate on credentials/network — guard live calls).

## Development & Testing

Standard R-package workflow (devtools/testthat; no Makefile):

```r
devtools::document()        # regenerate man/ and NAMESPACE from roxygen comments
devtools::load_all()        # load the package for interactive work
devtools::test()            # run testthat suite (edition 3)
devtools::check()           # full R CMD check (what R-CMD-check.yaml runs)
lintr::lint_package()       # style/lint per .lintr (matches lint.yaml)
covr::package_coverage()    # coverage (matches test-coverage.yaml)
pkgdown::build_site()       # build docs site (matches pkgdown.yaml)
```

CI workflows in `.github/workflows/`: `R-CMD-check.yaml` (build/check), `lint.yaml` (lintr), `test-coverage.yaml` (covr), `pkgdown.yaml` (docs site). Many tests touch the live API and `skip` without valid credentials/network — keep that guarding intact.
